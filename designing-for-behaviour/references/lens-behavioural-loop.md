# Lens: Behavioural Loop

**Source:** *Atomic Habits* (Clear), *Tiny Habits* (Fogg), *Hooked* (Eyal), merged into one loop model. One vocabulary: trigger → action → reward → investment.

A durable behaviour is a loop that gets easier and more valuable each cycle, not a one-shot funnel. It fires when motivation, ability, and a prompt meet at the same moment (Fogg's B = MAP).

Rate only what fits the product's natural frequency. A daily habit tracker and quarterly tax software are judged differently. For the latter most habit machinery is N/A, and forcing it in is bloat.

## Diagnosis order

When the behaviour isn't happening, find the **first** broken link. Fixing a later link won't help.

1. **No prompt** — nothing brings the user to the moment, or it is mistimed or ignored.
2. **Action too hard** — too many steps, value gated, needs skill or confidence the user lacks.
3. **Motivation too low** — check this last. Teams blame motivation by reflex when the prompt or the action is the real problem, and those are cheaper to fix.
4. **Reward missing, delayed, or unclear.**
5. **No investment** — nothing is stored, so the next cycle isn't loaded.

## 1. Target behaviour and loop existence *(behaviour)*

- Is there one specific, observable target behaviour (user + situation + action + completion), not "engage more"?
- Is it small enough for one session and frequent enough to repeat, given the real need?
- Can you name all four links, or are some missing?
- Is it the best behaviour to target (high user value, high business value, easy, already wanted), or just the first one someone thought of?
- Is there a minimum version that still counts on a low-energy day?

## 2. Trigger *(engagement, adoption)*

- **External:** does a concrete prompt point at exactly one action and land the user where they can do it now? Or does the product assume users will remember?
- **Internal:** is the product tied to a recurring need or feeling ("this is what I open when I'm unsure about X")?
- Does the trigger ride an existing routine ("after I ___, I ___")?
- Are triggers overused to mask weak value, training users to ignore them? Can users tune them?

## 3. Action *(behaviour, adoption)*

Making the action easier is almost always cheaper than raising motivation.

- Can the first meaningful action happen in seconds, or is value gated behind setup, forms, tutorials, or a paywall?
- Is there a starter step that leads into the real behaviour, not a trivial action disconnected from value?
- Is the tenth use faster than the first, or does every session reset to beginner mode?
- Is setup or browsing being mistaken for the behaviour?
- Is the action easier than the competing behaviour (the current workaround, the tempting distraction)?

## 4. Reward *(engagement, behaviour)*

- Does a reward arrive right after the action and satisfy the need that triggered it, not a decorative badge?
- Does the user clearly feel "that worked"? Or is the ending ambiguous?
- Where it fits, is there variability tied to real value (social, information, mastery)?
- Does it reward the behaviour you want repeated, not a vanity action?

## 5. Investment *(adoption, engagement)*

The link funnel thinking forgets.

- After value, does the user put something in (data, content, preferences, connections, history) that makes the product better for them next time?
- Does that investment load the next trigger (a scheduled item, a saved draft, a pending result)?
- Is prior work surfaced at the return moment, or reset?
- Is investment asked after value and kept small, not demanded up front?

## 6. Progress and recovery *(engagement, behaviour)*

- Is the behaviour that matters made visible as accumulating progress, without tracking vanity metrics?
- After a lapse, is re-entry easy ("never miss twice", restored context)? Or do all-or-nothing streaks turn one miss into abandonment?
- Does resuming after an interruption drop the user exactly where they were?

## 7. Compounding *(adoption)*

- Does repeated use reinforce an identity the user wants ("I'm someone who ships")?
- Does the loop strengthen with repetition into value the user would miss? Or does it collapse once novelty fades?
